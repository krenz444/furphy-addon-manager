## E1 - Rollback / version history

Wago website facts (send the same browser User-Agent as for CurseForge; pace >= 300 ms; on HTTP 429/503 wait 5 s and retry once; never use the official /api/external/* endpoints - they need a paid key):

A 409 means the version changed: re-read it from the HTML page and retry once. Cache the version in state.json.
- Addon details: `/addons/{slug}` JSON -> `props.addon` = {id (string like "ZKbxbRN1" = the `## X-Wago-ID` in .toc files), slug, display_name, summary, thumbnail_image (cdn url), categories[{id, display_name, icon}], website, source_url, support_url, discord_url, is_unlisted}, `props.description` (plain text/markdown), `props.metadata` = {last_update, download_count, like_count, developers[{name, avatar}], owner, recent_releases{retail{label, changelog,...}, ...}}.
- Releases: `/addons/{slug}/versions?page=N` JSON -> `props.releases` is a Laravel paginator {data[], current_page, last_page, per_page (10), total, next_page_url}; each release = {id (string like "r6p5g7zQ"), addon_id (int), size (bytes), label (version text), stability ("stable"|"beta"|"alpha"), changelog (markdown), created_at (ISO), supported_retail_patches[] (e.g. "12.1.0"), supported_classic_patches[], supported_mop_patches[], ..., download_link (signed URL `https://addons.wago.io/download/{id}?expires=&link=&signature=`, valid ~24 h)}. Possibly filterable with `?stability=`.
- Download: GET the signed download_link with redirects allowed -> 302 -> `https://cdn.wago.io/public/addons/{addonId}/{hash}/{name}.zip` (200, application/zip, Content-Length == release.size). Verify size. `/download?addonId={id}` is only an HTML landing page - do not use it.
- Search/browse: `GET https://addons.wago.io/?search={q}&game_version=retail[&category={categoryId}][&page=N]` JSON -> `props.addons` paginator (15/page) whose `data[]` items are server-rendered HTML CARD SNIPPETS, not objects: parse each with regexes for `href="https://addons.wago.io/addons/([a-z0-9-]+)"` (slug), the `<h3 ...>NAME</h3>` (display name), `src=(https://cdn.wago.io/thumbnails/...)` (thumbnail) and any summary/author/download-count text present; `props.allCategories` = [{id, display_name}] (29 entries); `props.sort` echoes a sort param (test values such as popular, updated, downloads, name and document which work). Full details for a card come from `/addons/{slug}`.
- Gallery/screenshots: `/addons/{slug}/gallery` JSON (props contain image URLs - inspect and document).

## E16 - Keyless mode

Goal: without a CurseForge API key, give CurseForge-sourced addons (identified by numeric `projectId`, no `wagoId` toc tag) as much of search/browse, descriptions, logos, screenshots, changelogs and compatibility as can honestly be gotten keylessly, on top of what E12 (Wago as a full second source) and the base build's keyless `mods/{id}/files` endpoint already provide. This never weakens or bypasses the key-gate on the official CurseForge API or attempts to defeat CurseForge's Cloudflare block in any way - it adds three new, independently-verified, purely additive metadata sources and defines exactly when each is consulted, in what order, relative to the key-gated path and to E12's existing Wago integration. None of the three new sources can install anything - they are read-only enrichment only; the only install-capable sources remain CurseForge's own keyless `files`/`files/{fileId}`/download endpoints (base SPEC, unchanged) and Wago (E12, unchanged).

Per-capability fallback order (this is the spec; CLI/Server/UI below implement it):
- **Search/Browse (CurseForge-hosted addons, no key)**: (1) the offline catalogue index built from `instawow-data`'s `base-catalogue-v8.compact.json`, refreshed at most once/24h, searched locally with zero live requests per query; (2) when that index returns few/no hits, a supplemental live fuzzy search against `addon-radar.com/search/__data.json?q=`, paced and cached, results badged distinctly as "live match" rather than "indexed"; (3) with a key: unchanged, the existing official `/api/cf/search` takes over entirely and neither (1) nor (2) is consulted. Wago's own search (E12) is a separate, always-available switch in the same Browse tab, unaffected by any of this.
- **ID -> name/slug resolution** (the internal step everything below depends on): (1) `instawow-data` catalogue entries with `source:"curse"` (100% coverage verified against all 37 of the user's installed CurseForge ids, refreshed daily); (2) `strongbox-catalogue`'s `curseforge-catalogue.json` (frozen since datestamp `2022-01-22`, 54% coverage verified against the same 37 ids) as cheap insurance for the rare id (1) might ever miss; (3) unresolved -> capabilities below fall to their own last resort.
- **Descriptions**: (1) official CF API `GET /v1/mods/{id}/description` (key); (2) a Wago match - either the record's own toc-derived `wagoId`/`slug` (E12) or a confident name+author search match (see "Wago auto-match" below) - via E12's existing `/api/wago/addons/{slug}` (`props.description`, plain text/markdown); (3) `addon-radar.com/addon/{slug}/__data.json`'s `description_html`/`summary` fields, slug from the ID resolution step above; (4) none - local record `name` only, explicit "no description without a key" placeholder.
- **Changelogs**: (1) official CF API `GET /v1/mods/{id}/files/{fileId}/changelog` (key); (2) a Wago match's `recent_releases.retail.changelog` / a release's own `changelog` field (E12, unchanged); (3) **none** - no source found in this investigation exposes CurseForge changelog text without a key (confirmed: `www.curseforge.com/api/v1/mods/{id}/files/{fileId}/changelog` -> 404 real-not-Cloudflare; `addon-radar.com`'s detail payload has no changelog field at all, grepped and absent; both catalogues carry no per-version data whatsoever). This is the one clean, permanent gap - the UI must show a dedicated empty state, never a blank tab or infinite spinner.
- **Logos**: (1) official CF API `mod.logo.thumbnailUrl`/`.url` (key); (2) Wago match's `thumbnail_image`; (3) addon-radar's `logo_url`; (4) existing colored-initial-letter tile fallback (base SPEC/E12, unchanged).
- **Screenshots**: (1) official CF API `mod.screenshots[]` (key); (2) Wago match's `/addons/{slug}/gallery` (E12's existing defensive renderer - shape still genuinely unconfirmed, per SPEC's own caveat); (3) addon-radar's `screenshots[]` (`{id,title,description,thumbnail_url,url}`, confirmed present as a field on the BigWigs detail page, though population was not verified for every addon); (4) existing empty state.
- **Compatibility**: unaffected by E16 - already fully keyless via E13 (toc `## Interface:` + the base build's already-keyless `mods/{id}/files` -> `gameVersions[]`). When an addon-radar detail was already fetched for descriptions anyway, its `game_versions[]` field may be shown as a secondary cross-check hint in the drawer, but E13's own compat computation is not changed or made to depend on it.
